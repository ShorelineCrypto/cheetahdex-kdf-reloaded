# EVM Swap V2 ABI JSON files

This directory ships two Ethereum contract ABI JSON files used by the
EVM atomic-swap V2 implementation:

- `maker_swap_v2_abi.json`
- `taker_swap_v2_abi.json`

## What they are

These files are **factual interface descriptions**: machine-generated
JSON metadata enumerating the function selectors, parameter types, and
event signatures of two on-chain Solidity contracts. They contain no
authored prose, no comments, no idiomatic structure choices — just the
contract surface as exported by the Solidity compiler.

## Provenance

The on-chain contracts (`MakerSwapV2`, `TakerSwapV2`) deployed by the
upstream KomodoPlatform deployment campaign are the canonical source of
truth for these ABIs. The ABI JSON is a deterministic byproduct of
compiling the Solidity source: any independent re-compilation of the
same source pinned to the same `solc` version produces a byte-identical
JSON modulo formatting.

The copies in this repository are the same JSON shipped by the upstream
analysis snapshot at `kdf-analysis-2022 origin/dev:mm2src/coins/eth/`.
We retain them byte-identical so:

1. The ABI matches the on-chain bytecode currently deployed (re-deriving
   it from a different `solc` version risks selector skew).
2. Existing audit traces and transaction decoders pinned to these
   ABIs continue to work unchanged.

## Legal status

ABI JSON files are interface descriptions, not creative expression.
Under *Feist Publications, Inc. v. Rural Telephone Service Co.*, 499
U.S. 340 (1991), facts and the obvious arrangements thereof are
uncopyrightable; the same logic is consistently applied to API surface
specifications (the Oracle / Google decision narrowed but did not
reverse this for purely functional metadata). A function-selector
table generated by a compiler from public bytecode is precisely such
an unprotectable interface fact.

For this reason the two ABI JSON files are intentionally maintained at
0% diff against the upstream snapshot. They are exempt from the 40%
diff-similarity gate that applies to authored Rust source under
`RELOADED-CODING-STANDARDS.md` §8.

## Updating the ABIs

If the on-chain contracts are upgraded:

1. Recompile the canonical Solidity source with the matching `solc`
   version.
2. Replace the JSON file in place.
3. Verify the `bytes4` selectors of every method called from
   `mm2src/coins/eth/eth_swap_v2/` against `cast keccak`.
4. Run `cargo test -p coins eth_swap_v2 --lib` to confirm the Rust
   bindings still decode the new ABI.

Do not hand-edit these files.
