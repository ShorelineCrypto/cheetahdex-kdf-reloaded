# Plan: reloaded v0.2.0 — dependency hygiene & advisory remediation

> **Status:** active. `dev` moved on to `0.3.0-alpha.1` (`8cf7820e7`) but this
> plan's advisory/hygiene tracking still applies — none of it is version-line
> specific. This plan tracks the security
> advisories currently *accepted* in [`deny.toml`](../../deny.toml) and the work
> needed to actually clear them. Update the matching row when an item lands;
> delete this file when every non-`upstream-blocked` row is done.
>
> The CI gate (`.github/workflows/audit.yml`, `cargo deny check advisories`,
> cargo-deny pinned to `0.19.9`) fails on any advisory **not** in `deny.toml`'s
> `ignore` list. So the workflow for each item below is:
> **fix the dependency → remove its `RUSTSEC-…` line from `deny.toml` → the gate
> stays green.** Removing an ignore line is the definition of "done".

## Suggested v0.2.0 ordering

1. **Cheap, independent wins first** (this file's "Compiler-warning
   follow-up" section + the secp256k1-migration.md "Lightning wasm-gating
   fix"): `web_sys` setter renames, stray `crossbeam` bump, Lightning
   Cargo.toml wasm-scoping. All mechanical, all low-risk, bundle under one
   `dep-hygiene` branch.
2. **MessagePack compatibility work:** provide and test an integer-variant
   serializer before moving `rmp-serde` to the patched 1.x line.
3. **secp256k1 0.20 → 0.29 migration** (`secp256k1-migration.md`): now scoped
   independently of the Lightning uplift; unblocks the real WASM link build.
4. **Solana SDK bump** (`solana-sdk-upgrade.md`) and **WalletConnect fork
   tungstenite bump** (`walletconnect-fork-upgrade.md`): independent of each
   other and of secp256k1; can run in parallel with or after it.
5. **Upstream tracking** (A libp2p fork): rebase the pin when
   `KomodoPlatform/rust-libp2p` lands a modern-rustls tag; not reloaded-side
   code work, no action until then.
6. **rust-lightning (LDK) uplift** (`lightning-ldk-upgrade.md`): largest,
   highest-risk, no advisory forcing function — do last, on its own extended
   timeline.

## Compiler-warning follow-up

- **`web_sys` deprecated IndexedDB/fetch setters.** Confirmed via
  `cargo check --target wasm32-unknown-unknown` (2026-08-06) on `mm2_db` and
  `mm2_net` — `web-sys 0.3.94` renamed several WebIDL-attribute-style methods
  to explicit `set_*` setters; the old names still work but warn:
  - `mm2src/mm2_db/src/indexed_db/drivers/upgrader.rs:36,37` —
    `IdbObjectStoreParameters::key_path`/`auto_increment` →
    `set_key_path()`/`set_auto_increment()`
  - `mm2src/mm2_db/src/indexed_db/drivers/upgrader.rs:67,82` —
    `IdbIndexParameters::unique` → `set_unique()` (two call sites)
  - `mm2src/mm2_net/src/wasm_http.rs:138,139,142` —
    `RequestInit::method`/`body`/`mode` → `set_method()`/`set_body()`/`set_mode()`
  Mechanical rename, identical semantics/return type (all are plain builder
  setters); no behavior change. Low-risk, bundle under the dep-hygiene branch.
- **Stray legacy `crossbeam` line via `common`.** `mm2src/common/Cargo.toml`
  pins `crossbeam = "0.7"` (used for `crossbeam::queue::SegQueue` in `log.rs`
  and `crossbeam::channel` in `executor/native_executor.rs`). That umbrella
  crate still resolves the old `crossbeam-channel 0.4.4` /
  `crossbeam-epoch 0.8.2` / `crossbeam-deque 0.7.4` family alongside the
  already-modern direct `crossbeam-channel 0.5.16` line used elsewhere in the
  graph (two families, confirmed via `cargo tree -i crossbeam@0.7.3`). Not a
  RUSTSEC finding — `crossbeam-channel`/`-deque`/`-epoch`/`-utils` are all in
  `deny.toml`'s `[bans].skip` list, so this doesn't fail CI — but it's exactly
  the kind of duplicate-family hygiene the 2026-08-05 audit refresh cleaned up
  elsewhere. Bump `crossbeam = "0.7"` → `"0.8"` in `mm2src/common/Cargo.toml`;
  both call sites (`SegQueue`, `channel::unbounded`-style usage) are stable
  long-term APIs present unchanged in 0.8. Verify with `cargo build -p common`
  + `cargo test -p common` after the bump.
- **Legacy WASM process-log tail.** `PROCESS_LOG_TAIL`, `TAIL_CUR`, and
  `append_log_tail` were introduced for an old integration-test log reader.
  They have no remaining Rust, JavaScript, or test consumer in this repository
  and are not browser-console exports. Their implementation is commented out
  during beta validation because `static mut` creates an unnecessary Rust 2024
  compatibility and future threaded-WASM safety risk. Before the production
  release, delete the commented implementation (recommended), or replace it
  with a safe owned ring buffer if a real consumer is identified. Leaving the
  commented implementation in the production release is not an accepted final
  state.

## Guardrails

- **Branching:** large/risky items (secp256k1 migration, Solana SDK bump,
  WalletConnect fork bump, Lightning LDK uplift) each get their own feature
  branch off `dev`, named to match their plan doc
  (`dep/secp256k1-0.29`, `dep/solana-sdk-2.x`, `dep/walletconnect-tungstenite`,
  `dep/lightning-ldk-uplift`). Small, mechanical, independently-reversible
  bumps (the "Compiler-warning follow-up" items, patch/point releases,
  single-manifest renames) are bundled under one shared `dep-hygiene` branch
  rather than a branch each — split out of it only if one turns out to need
  its own regression pass. `--no-ff -S` merge either way.
- Never merge a dependency bump without: `cargo build --release` + the affected
  crate's tests + clippy on the changed crate(s). Funds-touching crates
  (coins, db_common) additionally need their unit/integration tests.
- After any Cargo.lock change, `cargo deny check advisories` must stay green
  (the CI gate enforces this on PR).
- WASM-affecting changes: run the applicable local
  `--target wasm32-unknown-unknown` checks and retain CI as the complete
  cross-platform gate. For anything claiming to fix the secp256k1 WASM
  blocker specifically, `cargo check` is not sufficient proof — use
  `cargo build --target wasm32-unknown-unknown -p mm2_bin_lib --lib` (the
  actual link step) per `secp256k1-migration.md`.
- Commit each item once it independently builds/tests/lints clean; don't
  batch unrelated dependency bumps into one commit even on a shared branch.
