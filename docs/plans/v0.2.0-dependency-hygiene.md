# Plan: reloaded v0.2.0 — dependency hygiene & advisory remediation

> **Status:** active. dev is on `0.2.0-alpha.1`. This plan tracks the security
> advisories currently *accepted* in [`deny.toml`](../../deny.toml) and the work
> needed to actually clear them. Update the matching row when an item lands;
> delete this file when every non-`upstream-blocked` row is done.
>
> The CI gate (`.github/workflows/audit.yml`, `cargo deny check advisories`,
> cargo-deny pinned to `0.19.9`) fails on any advisory **not** in `deny.toml`'s
> `ignore` list. So the workflow for each item below is:
> **fix the dependency → remove its `RUSTSEC-…` line from `deny.toml` → the gate
> stays green.** Removing an ignore line is the definition of "done".

## Suggested v0.2.0 ordering

1. **MessagePack compatibility work:** provide and test an integer-variant
   serializer before moving `rmp-serde` to the patched 1.x line.
2. **Pinned secp256k1 path:** identify and upgrade its owning dependency without
   changing signing or wire behavior.
3. **Upstream tracking** (A libp2p fork, B Solana, C walletconnect/zcash):
   rebase pins as upstream fixes land; not reloaded-side code work.

## Guardrails

- Do each item on its own feature branch off `dev`; `--no-ff -S` merge.
- Never merge a dependency bump without: `cargo build --release` + the affected
  crate's tests + clippy on the changed crate(s). Funds-touching crates
  (coins, db_common) additionally need their unit/integration tests.
- After any Cargo.lock change, `cargo deny check advisories` must stay green
  (the CI gate enforces this on PR).
- WASM-affecting changes: verify via CI's WASM job (local WASM is blocked by a
  pre-existing `getrandom` build-config issue).
